# 研究室NASをUbuntu上にマウントする

最終更新: 2026-08 ／ 対象: WSL2上のUbuntu、SMB/CIFS共有

研究室のNAS（SMB共有）をUbuntuのディレクトリとしてマウントし、計算結果の保存や受け渡しに使えるようにします。起動のたびに自動でマウントされる設定まで行います。

NASのIPアドレスとログイン用のアカウントは、あらかじめ管理者に確認しておいてください。

---

## 手順0: 必要なパッケージをインストールする

SMB共有をマウントするためのツールを入れます。

```
sudo apt update
sudo apt install cifs-utils
```

---

## 手順1: マウント先のディレクトリを作成する

`/mnt` 以下にはWindowsの各ドライブがマウントされています。ここにNAS用のディレクトリを作ります。

```
sudo mkdir /mnt/nas
```

---

## 手順2: 認証情報ファイルを作成する

NASにアクセスするためのユーザ名とパスワードを、専用のファイルに記述します。こうしておくと `/etc/fstab` に直接パスワードを書かずに済み、記号を含むパスワードでのトラブルも避けられます。

ホームディレクトリにファイルを作成します。

```
vim ~/.smbcredentials
```

以下の内容を記述して保存します。NASにログインするためのユーザ名とパスワードです。

```
username=XXXXX
password=XXXXX
```

他のユーザから読まれないよう、権限を変更します。**この手順を省略しないでください。**

```
chmod 600 ~/.smbcredentials
```

---

## 手順3: UIDとGIDを確認する

マウントしたファイルの所有者を自分にするために、自分のUIDとGIDを調べます（通常はどちらも1000です）。

```
id -u
id -g
```

---

## 手順4: /etc/fstab を編集する

> **注意**: `/etc/fstab` の記述を誤ると、起動時にエラーが発生することがあります。次の手順5のテストを必ず実施してください。

設定ファイルを開きます。

```
sudo vim /etc/fstab
```

末尾に以下の1行を追加します。1行で記述してください。

```
//「NASのIPアドレス」/homes/「NASのユーザ名」 /mnt/nas cifs credentials=/home/「Ubuntuのユーザ名」/.smbcredentials,uid=1000,gid=1000,iocharset=utf8,_netdev 0 0
```

書き換える箇所は以下のとおりです。

- `「NASのIPアドレス」` `「NASのユーザ名」`: NAS側の情報。共有ディレクトリのパス（例では `/homes/...`）はNASの構成に合わせてください
- `「Ubuntuのユーザ名」`: 手順2でファイルを作ったホームディレクトリのパス
- `uid=1000,gid=1000`: 手順3で確認した数字

各オプションの意味は以下のとおりです。

| オプション | 意味 |
|---|---|
| `credentials=` | 手順2で作成したファイルの**絶対パス**を指定します。`~` は使えません |
| `uid=` `gid=` | マウントしたファイルの所有者を指定します |
| `iocharset=utf8` | 日本語のファイル名を正しく扱うための指定です |
| `_netdev` | ネットワークが接続されてからマウントします。これがないと、未接続時に起動が止まることがあります |

> **補足**: 以前の手順では `vers=3.0` を指定していましたが、省略すればクライアントとNASの間で使用可能な最も新しいSMBプロトコルが自動的に選ばれます（現行は3.1.1）。接続できない場合にのみ、`vers=3.0` や `vers=2.1` を明示して切り分けてください。

---

## 手順5: テスト（再起動前に必ず実施）

記述に誤りがないか確認します。

```
sudo mount -a
```

エラーが表示されなければ成功です。マウントされているか確認します。

```
df -h /mnt/nas
ls /mnt/nas
```

エラーが出た場合は `/etc/fstab` の記述を見直してください。エラーを残したまま再起動しないでください。

問題なければ、次回のWSL起動時から自動的にマウントされます。

> **補足**: WSLで `/etc/fstab` が起動時に処理されるかどうかは、`/etc/wsl.conf` の `[automount]` セクションにある `mountFsTab` の設定に依存します。既定では有効ですが、過去に設定を変更している場合は自動マウントされないことがあります。その場合は `/etc/wsl.conf` を確認してください。

---

## 手順6: シンボリックリンクを作成する

ホームディレクトリからNASへ辿れるようにしておくと便利です。

```
ln -s /mnt/nas ~/NAS
```

---

## トラブルシューティング

| 症状 | 確認すること |
|---|---|
| `mount error(13): Permission denied` | 認証情報ファイルのユーザ名・パスワード、およびNAS側のアクセス権限 |
| `mount error(112): Host is down` | NASのIPアドレス、ネットワーク接続、SMBプロトコルのバージョン（`vers=` の明示） |
| `mount error(2): No such file or directory` | NAS側の共有ディレクトリのパス |
| ファイル名が文字化けする | `iocharset=utf8` が指定されているか |
