# 計算サーバへの接続方法

最終更新: 2026-08 ／ 対象: Windows / macOS / Linux（クライアント側）

研究室の計算サーバ（Linux）に手元のPCから接続し、ファイルを転送して計算を実行するまでの手順です。サーバ側の設定は[計算サーバのSSH設定](../SSH_installation/README.md)を参照してください。

---

## 1. 準備

以下を管理者（教員）に依頼・確認してください。

- 計算サーバへのユーザアカウントの作成
- 計算サーバのホスト名（またはIPアドレス）とポート番号

手元の環境については、Windowsの場合はWSL上のUbuntu、macOSの場合はターミナルから作業します。以下のコマンドはいずれもそこで実行します。

---

## 2. SSH鍵の作成と登録

計算サーバへの接続には公開鍵認証を使います。パスワード認証は無効化されている場合があります。

### 鍵を作成する

```
ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519_server
```

- パスフレーズを聞かれます。空でも動作しますが、設定しておくほうが安全です
- `~/.ssh/id_ed25519_server`（秘密鍵）と `~/.ssh/id_ed25519_server.pub`（公開鍵）が作成されます
- **秘密鍵は他人に渡さないでください。** 渡すのは `.pub` が付いた公開鍵だけです

> 以前はRSA（`ssh-keygen -t rsa`）が使われていましたが、現在はed25519が推奨されます。鍵が短く、生成も検証も高速です。

### 公開鍵をサーバに登録する

サーバにパスワードでログインできる状態であれば、以下が最も簡単です。

```
ssh-copy-id -i ~/.ssh/id_ed25519_server.pub ユーザ名@ホスト名
```

パスワードログインが無効な場合は、公開鍵の内容を管理者に渡して登録を依頼してください。公開鍵は以下で表示できます。

```
cat ~/.ssh/id_ed25519_server.pub
```

## 3. SSH接続

### 接続設定を書く

毎回ホスト名やユーザ名を打つ代わりに、`~/.ssh/config` に設定を書いておきます。

```
vim ~/.ssh/config
```

```
Host server
  HostName xxx.xxx.xxx.xxx
  User sampleuser
  Port 22
  IdentityFile ~/.ssh/id_ed25519_server
```

- `Host`: 接続時に使う呼び名（任意の文字列）
- `HostName`: サーバのホスト名またはIPアドレス
- `User`: サーバ上の自分のユーザ名
- `IdentityFile`: 手順2で作成した**秘密鍵**のパス

設定ファイルの権限を確認します。

```
chmod 600 ~/.ssh/config
```

### 接続する

`Host` に書いた呼び名を指定します。

```
ssh server
```

初回は接続先の確認を求められるので `yes` と入力します。

切断するときは以下です。

```
exit
```

## 4. ファイルの転送

### Windowsの場合: WinSCP

GUIでファイルを操作したい場合に便利です。[公式サイト](https://winscp.net/eng/download.php)からインストールします。

- 「転送プロトコル」に SFTP、「ホスト名」にサーバのホスト名、「ユーザー名」に自分のユーザ名を入力します
- 「設定」→「認証」→「秘密鍵」で、手順2で作成した秘密鍵を指定します
- WinSCPはOpenSSH形式の鍵を読み込む際、PuTTY形式（`.ppk`）への変換を提案します。指示に従って変換してください
- 接続すると、左側にローカル、右側にリモートのファイルが表示されます。ドラッグ＆ドロップで転送できます

### macOS・Linuxの場合: sftp

macOSとLinuxには `sftp` が標準で入っています。手順3で `~/.ssh/config` を設定していれば、呼び名で接続できます。

```
sftp server
```

接続後の操作は以下のとおりです。

| 操作 | コマンド |
|---|---|
| リモートのディレクトリを移動 | `cd ディレクトリ名` |
| ローカルのディレクトリを移動 | `lcd ディレクトリ名` |
| リモートのファイル一覧 | `ls` |
| ローカルのファイル一覧 | `lls` |
| ローカル → リモートへ送る | `put ファイル名` |
| ディレクトリごと送る | `put -r ディレクトリ名` |
| リモート → ローカルへ取得 | `get ファイル名` |
| ディレクトリごと取得 | `get -r ディレクトリ名` |
| 終了 | `exit` |

（macOSでGUIのソフトを使いたい場合は、CyberduckやFileZillaが利用できます。）

### コマンド一発で転送する: scp / rsync

対話的に操作せず、その場で転送だけしたい場合に使います。

```
# ローカル → リモート
scp ./local_file.txt server:~/work/

# リモート → ローカル
scp server:~/work/result.txt ./

# ディレクトリごと同期する（差分のみ転送。大量のファイルではこちらが速い）
rsync -avh ./localdir/ server:~/work/localdir/
```

計算結果のように大量・大容量のファイルを繰り返し回収する場合は、`rsync` のほうが効率的です。

## 5. 長時間の計算を実行する

SSH接続を切断すると、実行中のプロセスも終了してしまいます。長時間の計算では以下のいずれかの方式を使います。**両者は同じ目的に対する代替手段なので、混ぜて使わないでください。**

### 方式A: tmux（推奨）

仮想的な端末を作り、その中で計算を実行します。接続し直せば元の画面に戻れるため、計算の様子をそのまま確認できます。

```
sudo apt install tmux    # 未導入の場合
```

| 操作 | コマンド |
|---|---|
| 新しいセッションを作る | `tmux new -s calc` |
| セッションから抜ける（計算は継続） | `Ctrl+b` を押してから `d` |
| セッションに戻る | `tmux attach -t calc` |
| セッションの一覧 | `tmux ls` |
| セッションを終了する | セッション内で `exit` |

使い方の流れは以下のとおりです。

```
tmux new -s calc                                    # セッションを作る

# セッション内で計算を実行する（画面に進捗が流れる）
mpirun -np 12 lmp -in in.melt 2>&1 | tee log.melt

# Ctrl+b を押してから d でセッションを抜ける → SSHを切断してよい
```

後日、接続し直して状況を確認します。

```
tmux attach -t calc
```

計算を中断する場合は、セッション内で `Ctrl+C` を押します。

> **ログの保存について**: `2>&1 | tee ファイル名` を付けると、進捗を画面に表示しながら、同じ内容をファイルにも保存できます。計算記録として残すほか、後から `grep` で特定の値を抽出する際に必要になるので、付けておくことをおすすめします。

### 方式B: nohup

tmuxが利用できない環境や、スクリプトから複数の計算をまとめて投入する場合に使います。コマンドの先頭に `nohup`、末尾に `&` を付けて実行します。

```
nohup mpirun -np 12 lmp -in in.melt > log.melt 2>&1 &
```

出力先を指定しない場合は `nohup.out` に書き出されます。画面には何も表示されないため、進捗はログファイルで確認します。

```
tail -F log.melt
```

表示を終了するには `Ctrl+C` を押します。計算はそのまま継続します。

実行中のジョブは以下で確認・操作できます。

```
jobs        # 実行中のジョブを確認
kill %1     # ジョブ番号1を停止する
```

> **注意**: `kill %番号` はジョブ番号を取り違えると別の計算を停止させてしまいます。実行前に必ず `jobs` で確認してください。

### 方式を混ぜないこと

tmuxのセッション内でさらに `&` を付けてバックグラウンド実行すると、画面には何も表示されず、`tail -F` を別途開く必要が生じます。tmuxを使う利点が失われるため、どちらか一方の方式で統一してください。
